# Scope Control

At task start, record the owner, acceptance criteria, permitted read scope, permitted write scope, and any explicitly excluded areas. Read scope and write scope are separate.

Evidence may justify targeted discovery within resources the user already placed in scope. It does not authorize a new repository, production system, external service, or mutation outside the task. A cross-repository edge is a reason to inspect an available dependency; it is not permission to change it.

At a phase change, re-establish the owner, active attachments, scope, and permitted next actions. A phase or owner change never silently grants durable-knowledge write access or resets an investigation budget.

Use a compact task record. Do not copy policy text or raw tool output into it.
