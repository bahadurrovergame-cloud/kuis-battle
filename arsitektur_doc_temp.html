Bab 1 • Ringkasan Sistem

1. Ikhtisar & Filosofi Desain Sistem

Kuis Battle Panggung adalah platform aplikasi cerdas cermat panggung interaktif real-time yang dirancang khusus untuk perlombaan tatap muka dengan 1 orang operator teknis. Sistem ini mengeliminasi kerumitan operasional kuis konvensional dengan membagi peran ke dalam 3 jenis layar yang sinkron seketika:

1. Layar Proyektor (/operator)

Dijalankan pada laptop panggung yang tersambung ke kabel HDMI proyektor/videotron & speaker panggung. Menyajikan visual utama, hitung mundur lingkaran SVG dinamis, suara detak (ticking SFX), papan kotak interaktif, dan podium juara.

2. Kontrol Operator (/control)

Dijalankan oleh 1 operator teknis di meja kendali. Dilengkapi shortcut keyboard [SPASI] untuk jeda/lanjut timer mikrofon tanpa me-reset sisa waktu, tombol tambah/kurang skor cepat, pembuka kunci jawaban, serta asisten AI Tutor.

3. Meja HP Peserta (/peserta)

Smartphone peserta yang ditaruh di meja masing-masing regu. Murni berfungsi sebagai Personal Live Scoreboard pasif. Dilengkapi Screen Wake Lock API agar layar tidak mati, tanpa tombol jawab (peserta menjawab lisan via mic).

Komponen / Layer Teknologi / Library Peran & Fungsi Utama

Prinsip Utama Arsitektur Single Source of Truth (SSOT)

Tidak ada kalkulasi skor atau timer yang disimpan terisolasi di sisi browser client. Seluruh waktu tersisa, status pertandingan (waiting, type_select, category_select, box_active, finished), skor regu, dan nomor soal aktif disimpan terpusat di tabel Supabase (game_sessions dan teams). Saat operator menekan tombol, perubahan state disebarkan dalam hitungan milidetik ke layar proyektor dan HP seluruh peserta.

Bab 2 • Diagram Alur Kerja

2. Alur Kerja Sistem (End-to-End System Flow)

Diagram Fase Perlombaan (5 Stepper Panggung)

1
Fase Persiapan & Pendaftaran Regu (Dashboard Hub '/')
Admin membuka dashboard pusat. Memilih atau membuat ruangan panggung (Multi-Room misal: KUIS88). Sistem meng-generate 3 QR Code khusus untuk proyektor, operator, dan HP peserta. Peserta memindai QR Meja & mendaftarkan nama regu beserta warnanya.
2
Fase Otentikasi Gatekeeper ('/login')
Operator atau Admin melakukan login PIN via POST /api/verify-pin. Role Operator (PIN 8888) diarahkan ke /control, sedangkan Admin Soal (PIN 123456) diarahkan ke /admin/soal. Token otorisasi disimpan aman di sessionStorage.
3
Fase Manajemen Konten & AI Generator ('/admin/soal')
Admin mengatur babak (Babak 1, Babak 2, Final), memilih jumlah kotak panggung, menginput soal manual atau men-generate puluhan soal instan melalui Google Gemini AI (POST /api/ai/generate-soal). Soal otomatis dipetakan ke kotak panggung (session_questions).
4
Fase Pertandingan Berjalan (Operator Control & Proyektor)
Operator mengontrol stepper 5 tahap panggung: Sambutan → Pilih Format Tantangan → Pilih Kategori → Buka Nomor Kotak → Soal Aktif. Saat peserta menjawab di mik panggung, operator menekan [SPASI] untuk menjeda waktu. Begitu selesai, operator menekan tombol penilaian [+100], [-50], atau skor custom, lalu membuka kunci jawaban dengan efek chime visual & audio.
5
Fase Evaluasi AI Tutor & Grand Final Podium
Operator dapat memicu AI Tutor (POST /api/tutor) untuk memberikan Hint Bertahap cerdas atau membacakan ulasan edukatif juri. Saat seluruh babak usai, status dialihkan ke finished, memicu VictoryPodium di layar proyektor dengan dentuman kembang api kaset canvas-confetti dan nada fanfare kemenangan.

Alur Komunikasi WebSocket & Realtime Supabase

[ Operator Laptop /control ]
       |
       | 1. Update Database (misal: is_timer_running = true, score += 100)
       v
[ Supabase PostgreSQL ] --- (Trigger Replication Identity) ---> [ Supabase Realtime Engine ]
                                                                       |
       +---------------------------------------------------------------+
       | (WebSocket Broadcast & postgres_changes Event)
       v                                               v
[ Layar Proyektor /operator ]               [ Smartphone Meja /peserta ]
 - Audio tick berbunyi detik demi detik       - Layar HP menyala terus (Wake Lock)
 - Timer SVG lingkaran berkurang              - Skor ter-update instan
 - Animasi buka kotak aktif                   - Flash layar Hijau (naik) / Merah (turun)
 - Pop-up kunci jawaban benar                 - Menampilkan peringkat langsung

Daftar Tabel & Relasi Data Supabase (PostgreSQL)

Nama Tabel Kolom Kunci & Tipe Fungsi & Realtime Streaming
categories id (UUID PK), name, description Katalog kategori lomba (Pengetahuan Umum, Sains, Sejarah, dsb.). Mendukung CRUD di tab Admin.
questions id (UUID PK), category_id (FK), type, question_text, options (JSONB), correct_answer, explanation, timer_duration, points Master bank soal. Mendukung 3 tipe: pilihan_ganda, benar_salah, dan essay. Metadata paket dan kotak disimpan via string serialisasi explanation.
game_sessions id (UUID PK), room_code (Unique), title, status, active_round, current_question_id (FK), is_answer_revealed, timer_remaining, is_timer_running Jantung Utama Pertandingan. Mengontrol jalannya lomba, status panggung, dan waktu. Disiarkan real-time melalui supabase_realtime.
teams id (UUID PK), session_id (FK), name, color, score, rank, members, member_count Data regu peserta per ruangan. Skor disinkronisasi instan ke scoreboard proyektor dan HP peserta.
session_questions id (UUID PK), session_id (FK), question_id (FK), round_name, box_number, is_opened Pemetaan spesifik soal ke babak (Round) dan nomor slot kotak di atas panggung (1 s/d 30 kotak).

src/lib/supabase.ts (Supabase Client, Types & Metadata Serializer) Core Library
Tanggung Jawab Inisialisasi klien Supabase, definisi seluruh interface tipe data TypeScript (Question, GameSession, Team, SessionQuestion), dan fungsi pembantu serialisasi metadata ruangan & kotak panggung.
Diimpor Oleh Hampir seluruh berkas proyek: src/app/page.tsx, src/app/control/page.tsx, src/app/operator/page.tsx, src/app/peserta/page.tsx, src/app/admin/soal/page.tsx, src/components/QuestionDisplay.tsx, src/components/Leaderboard.tsx, src/components/VictoryPodium.tsx, src/app/api/Keep-alive/route.ts.
Fungsi Kunci - parseQuestionMeta(q): Membaca tag [BOX:x] dan [PAKET:y] dari kolom penjelasan.
- buildExplanationWithMeta(...): Menyisipkan metadata kotak/paket ke dalam kolom penjelasan.
- parseSessionMeta(session): Mengekstrak jumlah kotak panggung [BOXES:x], filter kategori [CAT:y], dan tema panggung [THEME:key] dari judul room.
- buildSessionTitleWithMeta(...): Membungkus judul room dengan parameter kotak, kategori, dan tema.
- applyThemeToDom(themeKey): Mengaplikasikan tema aktif ke document.documentElement via atribut data-theme dan menyimpannya di localStorage.
- THEME_PRESETS: Preset 5 tema panggung (Midnight Slate, Auditorium Daylight, Royal Navy & Gold, Cyberpunk Neon, Emerald Zamrud).
src/lib/gemini.ts (Google Gemini Engine & Prompts) AI Core Library
Tanggung Jawab Inisialisasi Google Generative AI Provider via @ai-sdk/google, konfigurasi model (default: gemini-3.5-flash-lite), prompt engineering ketat untuk generator soal dan AI tutor, serta parser pembersih JSON anti-rusak.
Diimpor Oleh src/app/api/ai/generate-soal/route.ts, src/app/api/tutor/route.ts, dan src/app/admin/soal/page.tsx (tipe GeneratedQuestion).
Fungsi Kunci - getGeminiModel(customModel?): Mengambil API Key dari env dan me-return model instance.
- streamAiTutor(...): Mengembalikan streamText untuk petunjuk hint atau ulasan edukatif MC.
- generateQuizQuestions(...): Memanggil Gemini AI untuk memproduksi array soal kuis murni.
- cleanAndParseJson(raw): Membersihkan markdown code fences (```json) dan koma menggantung (trailing commas) agar JSON.parse tidak pernah error.
src/lib/sound.ts (Web Audio API Synthesizer) Audio Core Library
Tanggung Jawab Menghasilkan seluruh efek suara panggung secara real-time langsung melalui browser AudioContext (tanpa memerlukan file MP3/WAV eksternal sehingga 100% bebas dari kendala file missing / 404).
Diimpor Oleh src/app/operator/page.tsx, src/app/control/page.tsx, src/components/VictoryPodium.tsx.
Katalog Suara - playTick(isUrgent): Detak jam 600Hz segitiga (normal) atau 950Hz kotak (urgent di ≤ 5 detik).
- playTimeUp(): Buzzer waktu habis gelombang sawtooth turun dari 220Hz ke 110Hz.
- playScoreUp(): Nada semarak arpeggio akord C Mayor (C5 523Hz → E5 659Hz → G5 783Hz).
- playScoreDown(): Nada turun dramatis sawtooth dari 330Hz ke 165Hz.
- playCorrect(): Chime pembuka kunci jawaban akord 4 nada (C-E-G-C tinggi).
- playVictory(): Fanfare kemenangan 4 tangga nada untuk podium grand final.
src/hooks/useWakeLock.ts (Hook Web Screen Wake Lock) Custom Hook
Tanggung Jawab Mengakses API navigator.wakeLock browser agar layar smartphone peserta tidak pernah sleep / mati selama pertandingan panggung berlangsung.
Diimpor Oleh src/app/peserta/page.tsx.
Mekanisme Kerja Meminta sentinel wake lock saat peserta bergabung ke meja. Jika pengguna berpindah tab atau meminimalkan layar lalu kembali (event visibilitychange), hook secara otomatis mengaktifkan kembali wake lock.

Bab 6 • Konteks Khusus Gemini AI

6. Ringkasan & Panduan Konteks untuk Gemini AI

Catatan untuk AI Model (Google Gemini): Bagian ini merangkum aturan arsitektur mutlak, konvensi kode, pola deserialisasi metadata, dan instruksi penambahan fitur baru agar Anda dapat memberikan saran perbaikan atau kode ekstensi yang 100% kompatibel dengan arsitektur saat ini tanpa merusak sinkronisasi real-time.

Aturan Desain & Konvensi Kode Mutlak

  • Next.js 16 & React 19: Semua hook state client yang mendengarkan WebSocket Supabase atau Browser APIs (WakeLock, Fullscreen, Web Audio) HARUS memakai deklarasi 'use client'; di baris paling atas.
  • Zero External Audio File Dependency: DILARANG menambahkan referensi file statis audio .mp3 atau .wav di folder public. Seluruh efek suara baru HARUS dibuat sebagai metode di kelas SoundManager (src/lib/sound.ts) menggunakan native AudioContext browser (OscillatorNode & GainNode).
  • Sistem Serialisasi Metadata String: Supabase PostgreSQL saat ini tidak memiliki kolom terpisah untuk kotak babak dan filter kategori di tabel game_sessions. Sebagai gantinya, metadata disimpan sebagai tag regex di dalam kolom string:
    • Di game_sessions.title: Menyimpan tag [BOXES:12] (jumlah kotak) dan [CAT:uuid-kategori] (filter kategori aktif). Selalu gunakan parseSessionMeta() dan buildSessionTitleWithBoxes() dari @/lib/supabase.
    • Di questions.explanation: Menyimpan tag [BOX:1] (nomor kotak) dan [PAKET:Nama Paket]. Selalu gunakan parseQuestionMeta() dan buildExplanationWithMeta() dari @/lib/supabase.
  • Prinsip Layar Peserta Tetap Pasif: Jangan pernah menambahkan tombol input jawaban (misal tombol pilihan A/B/C/D) di src/app/peserta/page.tsx. Peserta selalu berdiskusi fisik di panggung dan menjawab lisan di mikrofon panggung.
  • Timer Real-time yang Tangguh: Timer tidak menggunakan setInterval murni yang mudah drift saat tab tidak aktif. Perhitungan sisa detik timer dihitung berdasarkan selisih waktu session.updated_at dengan Date.now().

Panduan Menambah Fitur Baru yang Sering Diminta

Kasus 1: Menambah Format Soal Baru (Misal: Soal Tebak Gambar)

  1. Tambahkan nilai enum baru ke PostgreSQL: ALTER TYPE question_type ADD VALUE 'tebak_gambar'; di Supabase SQL Editor.
  2. Perbarui union type QuestionType di src/lib/supabase.ts.
  3. Tambahkan kolom URL gambar (atau simpan format URL di question_text).
  4. Buka src/components/QuestionDisplay.tsx dan buat blok rendering question.type === 'tebak_gambar'.
  5. Buka src/app/control/page.tsx dan src/app/operator/page.tsx untuk menambahkan tab format soal baru tersebut.

Kasus 2: Menambah Efek Suara Baru (Misal: Buzzer Rebutan Panggung)

  1. Buka berkas src/lib/sound.ts.
  2. Tambahkan method baru, misalnya playBuzzerRebutan() dengan osilator frekuensi 150Hz gelombang sawtooth.
  3. Panggil method tersebut di src/app/control/page.tsx saat tombol pemicu ditekan.

Kasus 3: Menyesuaikan Model Gemini AI

  1. Buka berkas src/lib/gemini.ts pada fungsi getGeminiModel.
  2. Model default saat ini adalah gemini-3.5-flash-lite (tercepat dan paling stabil di AI Studio). Anda dapat menggantinya via environment variable GEMINI_MODEL=gemini-2.5-flash di berkas .env.local.
